# Наш маршрут

Общий планировщик поездок для компании друзей. Каждый добавляет места, голосует, вместе раскладываем по дням.
Владелец: Алексей. Общаться по-русски, коротко и по делу.

## Как это устроено

- **Один файл `index.html`**: HTML + CSS + JS, без сборки и без npm. Не дробить на модули без запроса.
  Рядом только обвязка: `sw.js` (офлайн), `manifest.webmanifest` и иконки `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (установка на экран «Домой»), `google-maps-resolver.gs` (см. ниже).
- **Хостинг**: GitHub Pages из ветки `master`, корень репозитория. Сайт: https://alexey-papitich.github.io/nash-marshrut/
  Изменения появляются на сайте через ~1 минуту после `git push`.
- **База**: Firebase Firestore, проект `nash-marshrut` (личный Google-аккаунт Алексея). SDK: Firebase compat 10.12.2 с gstatic.
  Конфиг (`firebaseConfig`) лежит прямо в `index.html`; это публичные ключи, так и задумано.
- **Правила базы**: `firestore.rules`. Это копия; применяются они только после публикации в Firebase Console → Firestore → Rules → Publish.
  Меняешь правила в файле → напомни Алексею опубликовать.
- **Карта**: Leaflet 1.9.4 (cdnjs) + стандартные тайлы OpenStreetMap (`tile.openstreetmap.org`, без ключа). Тёмная тема получается CSS-фильтром на `.leaflet-tile-pane`. CARTO без API-ключа больше не работает: вместо тайлов отдаёт заглушку «API KEY REQUIRED».
- **Телефон — основной сценарий.** Цели для пальца не меньше ~34px, никакой горизонтальной прокрутки на ширине 375px, отступы safe-area у шапки и таб-бара.
- **Поиск мест**: Nominatim (OpenStreetMap) прямо из браузера, не чаще раза в секунду (`nominatim()` сама выдерживает паузу). Полные ссылки Google Maps (`@lat,lng`, `!3d…!4d…`) парсятся локально.
- **Короткие ссылки `maps.app.goo.gl`** браузер раскрыть не может (CORS). Их разворачивает `google-maps-resolver.gs`, веб-приложение Google Apps Script под аккаунтом Алексея; его URL лежит в константе `RESOLVER` в `index.html`.
  Цепочка: короткая ссылка → 302 на `maps.google.com?q=<название, адрес>&ftid=…` → страница Google, в ней ссылка `/maps/preview/place?…` → оттуда точные координаты. Если `RESOLVER` пуст или упал, ищем по названию через Nominatim.
  Код `.gs` правится в репозитории, но работает только после «Развертывание → Управление развертываниями → Изменить → Новая версия» на script.google.com. Поменял файл → напомни Алексею.
  Проверка локально без деплоя: прогнать `doGet` в node с заглушками `UrlFetchApp` и `ContentService`, которые ходят в сеть через curl.
- **Офлайн**: `sw.js` отдаёт страницу из сети (таймаут 4 с) с фолбэком на кэш, CDN-скрипты и шрифты из кэша, тайлы OSM через кэш с потолком. Firestore, Nominatim и `RESOLVER` не трогает. Данные без сети даёт persistence Firestore. Меняешь список CDN-файлов → подними версию кэша `SHELL`.

## Доступ

Без регистрации: человек открывает ссылку и выбирает своё имя из списка участников поездки (хранится в localStorage на устройстве).
Писать в базу может любой, у кого есть ссылка. Это осознанный компромисс ради простоты.

## Данные (Firestore)

`trips/{id}`:
- `name`, `city`: строки
- `admins`: массив имён. Только они удаляют дни и меняют даты; если поля нет, админ Алексей (`admins()` в коде). Проверка только в интерфейсе, входа нет
- `members`: массив имён
- `days`: массив дат `YYYY-MM-DD`
- `center`: `{lat, lng}` для центра карты
- `createdAt`: ISO-строка

`places/{id}`:
- `tripId`, `name`, `category` (food | coffee | museum | view | walk | shop | other; неизвестные, например бывшие `bars`, показываются как other)
- `area`, `address`, `why`, `link`
- `lat`, `lng` (или null)
- `price` ('' | бесплатно | $ | $$ | $$$), `duration` (мин), `booking` (bool), `indoor` (bool)
- `addedBy`, `createdAt`
- `day` ('' = не в плане), `order` (порядок внутри дня), `done` (были)
- `votes`: `{ "Имя": 2 | 1 | -1 | 0 }`, где 2 «очень хочу», 1 «можно», -1 «пропущу», 0 голос снят
- `kind`: `'base'` у опорных точек (жильё, аэропорт, точка сбора), у обычных мест поля нет. `baseType`: home | transport | meet | other.
  Опорные точки не голосуются, не попадают в список мест, план и выбор мест для дня. Они всегда на карте (квадратный значок, кнопка «Домой»), а маршрут дня и «Упорядочить по пути» идут от ближайшего жилья (`homeFor`).

Голоса и другие вложенные поля обновляются точечно через `FieldPath` (функция `flatten` в коде), чтобы не затирать чужие голоса.
Первая поездка `nyc-2026` (Нью-Йорк, 24–28 октября 2026, 8 человек) создаётся автоматически, если коллекция `trips` пуста.

## Устройство кода (index.html)

- `S`: всё состояние. `render()` перерисовывает текущую вкладку (листы в `#sheet-root` не трогает). `softRender()` вызывается на чужих правках: если открыт `<select>` в `#main`, откладывает перерисовку до blur, иначе на iPhone выбор теряется.
- `tripPlaces()` отдаёт только обычные места, `tripBases()` только опорные точки, `findAny(id)` любые (для карты, правки и `show-map`).
- Вкладки: `renderPlaces`, `renderMap`, `renderPlan`, `renderTrip`. Модальные листы: `openSheet`, `openPlaceForm`, `openPicker` (точка на карте), `openDayPicker`, `openTripForm`.
- Все клики идут через один обработчик по `data-act`.
- Запись: `write(() => placeRef(id).update({...}), 'тост')`. Несколько документов сразу пишутся через `batch([[col, id, patch], ...])` (порядок в дне, удаление дня). Без сети `write` не ждёт сервер: Firestore держит запись в очереди (persistence включён).
- Чтение живое через `onSnapshot` на `trips` и `places`.
- Всё из базы выводить только через `esc()`, в том числе в атрибутах (`data-day`, `value`). Писать в базу может кто угодно, так что там бывает что угодно. Длительность читать через `dur(p)`.
- Форма места (`openPlaceForm`): ссылка первой, кнопка «Вставить» (`navigator.clipboard`), текст «Поделиться» разбирается в `takeText`. `findPlace` даёт `src`: `link` / `google` — точные координаты, `search` — по названию (не перетирает сохранённую или поставленную вручную точку). Категорию угадывает `catOf` по типу OSM, пока её не трогали руками. У места без точки форма при открытии сама запускает поиск.
- Геолокация (`locate`, `S.here`) включается только по кнопке «Где я» или сортировке «Рядом со мной», живёт в памяти и в базу не пишется.
- `LMap` создаётся сразу с центром. Без начального вида Leaflet падает на слоях, добавленных до `load`.
- Цвета: токены в `:root`, тёмная тема через `prefers-color-scheme`. Категории в стиле значков метро NYC.

## Проверка перед пушем

- Открыть `index.html` локально (`npx serve .` или просто в браузере) и пройтись: добавить место, проголосовать, назначить день, открыть карту.
- Сайт работает с живой базой даже локально, так что тестовые записи потом удалить.
